The fundamental conflict: constraint A requires a darker fill (lower L → more luminance contrast with near-white fg). Constraint B requires a lighter/brighter red (higher L → more contrast against near-black backgrounds). These two pull in opposite directions. There is no single L value that satisfies both at the 4.5:1 text level.

Split: the dead zone

Constraint A passes for L ≤ 0.57 (A = 4.51:1 at the boundary — barely).
Constraint B (text, all-surface) cannot pass at L ≤ 0.57 because the popover background (lum 0.022) is too close to the red at that lightness. B5 (popover) tops out at 2.95 at L=0.57.
There is no overlap — a split is required.

Verdict: SPLIT required

A single --destructive token CANNOT satisfy both constraints simultaneously at the 4.5:1 text threshold. A split into a fill token (for buttons) and an accent token (for text/icons on dark backgrounds) is necessary.

Alternatively, if you want every text-destructive instance (including small 10px form-field errors) to be AA-compliant even on the popover surface, you need L ≥ 0.67 for the accent token (which yields ~4.5:1 on popover). Check: at L=0.67, B5 popover ≈ 4.45:1 — still marginal. At L=0.70 the popover clears 4.5 easily, but the red becomes noticeably orange-pink. The practical recommendation is to accept that small red error text inside popovers is icon-level only (the popover has the lightest dark surface at lum=0.022), or to darken the popover background slightly.

AdminReviewTab gotcha (hardcoded text-white)

src/components/admin/AdminReviewTab.tsx uses text-white (not text-destructive-foreground) on bg-destructive buttons. At current L=0.63, white-on-destructive = 3.85:1 FAIL. Using the recommended fill token at L=0.50, white-on-fill = 6.67:1 PASS. These buttons should be migrated to use the standard button variant, or the fill token must be applied.

Implementation sketch

/* src/styles.css — two-token split */
--destructive:          oklch(0.65 0.2 26);   /* text-destructive / border / tints */
--destructive-fill:     oklch(0.50 0.2 26);   /* bg-destructive button fill        */
--destructive-foreground: oklch(0.97 0.01 26); /* unchanged                         */

/* button.tsx — destructive variant */
"border-destructive-fill bg-destructive-fill text-destructive-foreground hover:bg-destructive-fill/90"

/* badge.tsx — same swap */
"border-transparent bg-destructive-fill text-destructive-foreground"

All text-destructive, border-destructive/30, bg-destructive/10, and bg-destructive/20 tint usages keep the current token name — only the fill surfaces need the new token.
