# Grok Build model attribution, pricing, and coverage evidence

Research date: 2026-09-08. Resolves the investigation in [Establish Grok Build model attribution, pricing, and coverage constraints](https://github.com/alp82/aistack/issues/366). This is evidence for planning, with remaining product decisions identified below. No implementation, account access, production inspection, or publication was performed.

The vendor source inspected is xai-org/grok-build revision `75810042ca2762aa0b0fa17864f3f68823ccbea5`. AI Stack was inspected at `71cf6fdc98fecbb1f180b7e3c3dc07fb4eee9d08`. Source links below pin the vendor revision; repository-relative links identify the integration seams. No current real installation fixture was available to establish that the shipping binary has this exact behavior.

## Findings that constrain the plan

Grok Build can provide observed token counts partitioned by model for persisted turns, but its usage summary alone cannot prove the serving provider, whether a model key was reported or inferred, every request's timestamp, or full account consumption. Costs and token coverage are separate questions. The plan must retain uncertainty instead of allowing a successfully parsed summary to imply complete or exact measurement. Sources: [usage summary shape](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/usage_file.rs#L26-L85), [model attribution fallback](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-chat-state/src/actor/mutations.rs#L426-L448), [missing-usage path](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/acp_session_impl/sampler_turn.rs#L2127-L2159).

### Model and provider identity

`UsageSummary.modelUsage` is populated from the ledger's `by_model`. `primaryModelId` selects the model with the most calls, breaking ties with tokens. It is a summary label, unsuitable for assigning a mixed turn's tokens. Consume the per-model breakdown and preserve model changes. Subagent entries also fold into that breakdown. Sources: [summary construction and primary selection](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/usage_file.rs), [ledger folding](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-chat-state/src/usage.rs#L113-L161).

A main-loop call prefers the assistant response's nonempty model ID, then falls back to `state.sampling_config.model`. The persisted model key carries no flag distinguishing those origins. Responses conversion takes `response.model`; Messages conversion takes `resp.model`. This establishes reported model evidence where that field is present, but not a universal guarantee for every aggregate key. Sources: [recording](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/acp_session_impl/sampler_turn.rs#L2130-L2147), [fallback](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-chat-state/src/actor/mutations.rs#L426-L448), [Responses conversion](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-sampling-types/src/conversation/responses.rs#L5-L6), [Messages conversion](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-sampling-types/src/conversation/messages.rs#L385).

Grok supports custom model names, separate wire `model` IDs, built-in overrides, alternate API endpoints, provider definitions, and inference endpoint environment overrides. The current config cannot establish which historical endpoint served a prior turn after configuration changed. The usage summary has no provider or endpoint field. Therefore a `grok-...` key or the Grok Build harness name alone cannot authorize an `xai:` pricing key. An arbitrary custom endpoint also cannot be classified as free merely because its URL is localhost. These are inference boundaries, not findings that every other persisted source lacks historical provider evidence. The possible historical event/config join remains to be proven. Sources: [custom models](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-pager/docs/user-guide/11-custom-models.md), [summary fields](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/usage_file.rs#L26-L63).

AI Stack resolves catalog aliases separately from provider-qualified pricing. A gateway needs its own rate; an unresolved ID retains tokens. Retain that distinction for custom Build models. Do not invent catalog aliases to turn a requested alias into a verified served model. Sources: [catalog resolution](../../convex/lib/modelCatalog.ts), [provider and alias lookup](../../packages/pricing/src/table.ts).

### Tokens, missing usage, and completeness

Grok's normalized prompt count includes cache reads and cache creation. For AI Stack's disjoint buckets, fresh input is `inputTokens - cachedReadTokens - cacheCreationTokens`; output retains reasoning as a subset, without adding it again. Ledger total is input plus output; the source explicitly warns that Responses wire total can represent live context length. Validate nonnegative, finite, safe integer counts and bucket consistency before folding; malformed rows must be diagnosed instead of silently clamped into plausible counts. Source: [normalized token shape](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-sampling-types/src/conversation.rs#L724-L740), [ledger total](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-chat-state/src/usage.rs#L1-L4).

There is no cache-write TTL in the normalized token shape or persisted summary. Unknown writes belong in AI Stack's `cacheWriteUnsplit` category. The current backend prices that category with its 5-minute fallback policy. That is insufficient evidence for exact TTL-sensitive repricing of a custom provider. Sources: [token shape](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-sampling-types/src/conversation.rs#L724-L740), [wire and repricing policy](../../convex/lib/reprice.ts).

`usageIsIncomplete=true` establishes missing coverage. Its absence does not prove complete coverage: the response recorder explicitly leaves missing usage unmarked outside certain budget/retry contexts. Side calls such as compaction are excluded from the ledger. `costIsPartial` is independent: it means at least one cost was received and some calls had no cost. A summary may have useful observed tokens while every cost is absent. Sources: [missing-usage path](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/acp_session_impl/sampler_turn.rs#L2130-L2159), [ledger scope and partial-cost definition](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-chat-state/src/usage.rs#L1-L79).

AI Stack's current payload coverage counts parser files/lines, and `excludedTokens.unpriced` counts observed tokens lacking a price. Neither expresses unknown missing token quantities or upstream incompleteness. Required planning work is to carry upstream coverage status through daily ingest, folds, approval summaries, and public statistics without claiming a numerical percentage of unknowable missing tokens. Price coverage can still mean the share of observed tokens priced. Source: [payload coverage](../../packages/cli/src/harness/shared/payload.ts), [price coverage](../../convex/lib/reprice.ts).

### Time and dollars

Persisted `endedAt` is assigned with `Utc::now()` when turn usage is saved. One turn can contain multiple model calls and cross midnight or a pricing boundary. Using completion time as every call's timestamp is an attribution convention, not exact per-response pricing. Source: [persistence](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/persistence.rs#L2421-L2456).

The apparent per-response alternative is unavailable to a historical file reader: `response_completed` supplies per-response counts, but its actual call site uses `send_buffered_xai_update`. That route forwards buffered xAI notifications to the gateway without persistence or hook dispatch. The generic notification path's timestamp and persistence behavior does not apply to this event. Its constructor also supplies no model or cost. Thus this event does not repair historical timestamp or model allocation in `usage.json`. Sources: [call site](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/acp_session_impl/turn.rs#L3337), [buffered emission](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/acp_session_impl/updates.rs#L326-L374), [response constructor](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/acp_session_impl/updates.rs#L981).

xAI's public API documents cost ticks as the billed request cost after discounts, including server-side tool costs, with `10^10` ticks per USD. This API guarantee must not be expanded to every custom provider or OAuth subscription reading merely because a Build sidecar uses similarly named fields. Build's documentation keeps interactive billing and credits on `/usage`; its normalizer drops zero and negative ticks as unreported. An absent or zero source cost consequently cannot establish free inference or zero actual subscription expenditure. Sources: [API cost contract](https://docs.x.ai/developers/cost-tracking), [Build usage contract](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-pager/docs/user-guide/17-sessions.md#the-grok-usage-subcommand), [zero-cost normalization](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-sampling-types/src/conversation.rs#L811-L816).

Never copy `costUsdTicks / 1e10` into `apiEquivalentUSD` with a price-table citation. That field means a reconstruction from dated rates. Vendor-reported cost needs a separate basis, provenance, coverage, and consent contract if included. Preserve integer ticks safely until conversion, and do not label a session subset the account bill. Sources: [payload dollar contract](../../packages/cli/src/harness/shared/payload.ts), [backend dollar contract](../../convex/lib/reprice.ts), [ledger scope](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-chat-state/src/usage.rs).

The backend preserves all published `apiEquivalentUSD` as exact and fills only absent dollars using the cheapest period in the reading window. Adding turn-end estimates to the current field would silently gain an exactness claim. The plan needs either proven call-level attribution or an explicit estimated-cost basis carried end to end. Merely withholding CLI dollars does not solve unknown provider identity: bare model IDs can still be priced at read time. Source: [repricing and preserved published costs](../../convex/lib/reprice.ts), [shared price lookup](../../packages/pricing/src/table.ts).

## Concrete integration seams

- Add xAI to `Vendor`, the `PROVIDER_VENDOR` map, and the explicit accepted-vendor list in `parsePriceTable`. Omitting the parser change silently strips wire vendor information. Use a fixture-established provider spelling. Source: [shared table](../../packages/pricing/src/table.ts).
- Add xAI catalog-provider normalization to `vendorOfProvider`, which supplies served-row metadata and backend hints. The import allowlist already maps `xai` to `xAI`; it does not currently fix pricing identity by itself. Sources: [catalog](../../convex/lib/modelCatalog.ts), [import](../../convex/lib/modelImport.ts).
- Obtain real catalog/rate coverage only during implementation using the authorized database-mirror procedure. This report proves no production model or price row. Add dated rows with real source citations when needed; update bundled fallback rates only deliberately. Sources: [catalog loader](../../convex/lib/modelCatalog.ts), [repository pricing policy](../../AGENTS.md).
- Extend measurement coverage and cost-basis contracts before emitting claims unsupported by the current payload. Preserve `publishCost` at both ends and avoid backend repricing of unresolved provider evidence. Sources: [payload](../../packages/cli/src/harness/shared/payload.ts), [repricing](../../convex/lib/reprice.ts).
- Use optional workflow blocks where evidence is absent. Turn model totals cannot generate per-call Context histograms or separate main/subagent routing by themselves. `HarnessDay.context`, `routing`, `thinking`, duration, and phase atoms each require their own evidence. Source: [daily workflow contract](../../packages/workflow-rules/src/daily.ts).

## Decisions still required

1. Which persisted evidence is authoritative for historical model/provider attribution, and what conservative representation survives when the join fails? A real sanitized fixture must include alias, model switch, custom endpoint, and mixed parent/subagent cases.
2. Which timestamp and price-basis contract should summary-only history use? Completion-day counts and explicit estimates are possible, but must not acquire exact-call semantics downstream.
3. Should vendor-reported cost be exposed in this support effort, and with what evidence and subscription wording? Research establishes the distinction but does not choose the product scope.
4. How will incomplete or absent usage appear in approval and public stats? Preserve observed totals with explicit coverage, and keep unknown coverage separate from measured zero.

Acceptance evidence should exercise xAI vendor metadata round trips, direct versus gateway versus unknown provider pricing, reported versus fallback model IDs, mixed-model turns, cache conservation, missing/partial/zero costs, safe tick integers, missing usage without an incomplete flag, midnight/repricing boundaries, and cost consent. These are proposed checks derived from the source constraints above. No live sync is required to test them.
