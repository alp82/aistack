# Cursor usage repositories: breadth-first survey

Research date: 2026-09-10. Companion evidence for the Cursor harness gap investigation.

## Result

Existing open-source implementations materially narrow the uncertainty. Personal Cursor usage history, four token buckets, model identifiers, event timestamps, and conversation joins have implemented acquisition paths. Those paths include private dashboard JSON, private Connect RPC, and dashboard CSV. Reading private SQLite is not the only possible starting point: one implementation joins cloud usage events to retained local JSONL transcripts, and another exchanges a user-created API key for a bearer token without reading Cursor's database. These are implementation precedents, not a vendor compatibility guarantee.

The remaining integration question is whether AI Stack can validate completeness, ownership, missing fields, and joins across current versions and account types. An assertion that personal integration must start collecting only after installation is too strong. An assertion that historical tokens and conversation joins are unavailable is contradicted by the inspected code.

No downloaded tool was executed. No user credentials or private Cursor history were read. Source files, repository metadata, bundled fixtures, and tests were inspected. A fixture proves the repository exercises a shape; it does not independently establish the server currently returns it.

The first pass classified data acquisition approaches before selecting implementations for source inspection. Repository popularity was not treated as proof of correctness.

## Personal JSON and retained transcript joins are implemented

`chocolatemale/cursor-usage` fetches `/api/dashboard/get-filtered-usage-events` with explicit start/end timestamps and pagination. It reads `conversationId`, falls back to `cloudAgentId`, and keeps an unknown bucket. It groups by conversation, sums the four API token buckets, records first/last event times and models, and uses `chargedCents` before `tokenUsage.totalCents`. This is direct code evidence for a personal cloud usage path. [Acquisition and grouping](https://github.com/chocolatemale/cursor-usage/blob/a2f298f161f797036bf96718455e03ccdb42bef4/scripts/fetch_cursor_usage.py#L345), [token and cost fields](https://github.com/chocolatemale/cursor-usage/blob/a2f298f161f797036bf96718455e03ccdb42bef4/scripts/fetch_cursor_usage.py#L136).

Its local join traverses `~/.cursor/projects/**/agent-transcripts/**/*.jsonl`, takes the transcript filename stem as the conversation ID, identifies subagent parent IDs from directory nesting, and records the parent project directory. The first user message supplies a title. This is an ID-based join, not nearest-timestamp guessing. It does not prove every API conversation has a local transcript or that a path-derived project label is a canonical repository identity. [Join implementation](https://github.com/chocolatemale/cursor-usage/blob/a2f298f161f797036bf96718455e03ccdb42bef4/scripts/fetch_cursor_usage.py#L204).

The script also reads private macOS cloud-agent repository rows and Grok Bot persistence. Account usage can span product surfaces, so treating all fetched events as this machine's Cursor IDE activity is unsafe. Its own `product_of` splits cloud, Grok and IDE, but defaults unmatched IDs to IDE. AI Stack would need an explicit unknown-source state and observed join coverage. [Local product metadata](https://github.com/chocolatemale/cursor-usage/blob/a2f298f161f797036bf96718455e03ccdb42bef4/scripts/fetch_cursor_usage.py#L234), [product classification](https://github.com/chocolatemale/cursor-usage/blob/a2f298f161f797036bf96718455e03ccdb42bef4/scripts/fetch_cursor_usage.py#L301).

`iair0007/cursor-usage` independently groups events by conversation, retaining an unattributed group, and resolves names from `composer.composerData`, legacy chat indexes, or `cursorDiskKV` rows keyed `composerData:<id>`. Its SQL selects only the name field from specific IDs. This is a narrow private-SQLite enrichment seam, distinct from extracting usage tokens from SQLite. [Conversation grouping](https://github.com/iair0007/cursor-usage/blob/259ce8a426faf849592ddacb3cb24aae5caed1de/src/shared/usageLogic.ts#L703), [SQLite reader](https://github.com/iair0007/cursor-usage/blob/259ce8a426faf849592ddacb3cb24aae5caed1de/src/conversations.ts#L34), [version-dependent index parsing](https://github.com/iair0007/cursor-usage/blob/259ce8a426faf849592ddacb3cb24aae5caed1de/src/shared/conversationTitles.ts#L15).

## Personal API-key acquisition is a concrete alternative

`cnwinds/cursor-pulse` posts a personal user API key to `https://api2.cursor.sh/auth/exchange_user_api_key`, caches the returned access token in memory using JWT expiry, and calls `/aiserver.v1.DashboardService/GetFilteredUsageEvents` with bearer auth and the Connect protocol header. It pages with date bounds and retries token exchange on 401. Its mapper consumes `conversationId`, timestamp, model, input, output, cache read, cache write and cents. [Authentication and RPC](https://github.com/cnwinds/cursor-pulse/blob/6017130f010fe5a000550cf87dbefdd3b5f0cb9a/pulse/integrations/cursor_api.py#L171), [mapping](https://github.com/cnwinds/cursor-pulse/blob/6017130f010fe5a000550cf87dbefdd3b5f0cb9a/pulse/integrations/cursor_api.py#L98), [pagination](https://github.com/cnwinds/cursor-pulse/blob/6017130f010fe5a000550cf87dbefdd3b5f0cb9a/pulse/integrations/cursor_api.py#L271).

The bundled sample contains a `conversationId`; tests exercise mapping and token refresh with mocked HTTP. The repository explicitly describes these as reverse-engineered private APIs. Consequently, the source establishes an existing implementation, not verified live availability for every personal plan. [Fixture](https://github.com/cnwinds/cursor-pulse/blob/6017130f010fe5a000550cf87dbefdd3b5f0cb9a/tests/fixtures/cursor_usage_events.json), [tests](https://github.com/cnwinds/cursor-pulse/blob/6017130f010fe5a000550cf87dbefdd3b5f0cb9a/tests/test_cursor_api.py), [author's API notes](https://github.com/cnwinds/cursor-pulse/blob/6017130f010fe5a000550cf87dbefdd3b5f0cb9a/docs/cursor-usage-api.md).

This matters for setup design: copying browser cookies and silently extracting Cursor credentials are not the only researched choices. A user-provided key is a candidate, pending validation of scopes, revocation, lifetime and account coverage. No credential operation was performed during this research.

## CSV provides historical token data with weaker identity

`cstats` calls `/api/dashboard/export-usage-events-csv` with `startDate`, `endDate`, `strategy=tokens` and a session cookie. Its required columns include Date, Kind, Model, Max Mode, both input categories, Cache Read, Output Tokens, Total Tokens and Cost. It preserves the timestamp, computes daily/model aggregates and labels its computed cost `estimatedCost` while retaining `csvCost` separately. Its sample Cost values include `Free`, demonstrating why a CSV cost cell cannot always be parsed as a dollar amount. [Fetch and parser](https://github.com/robinebers/cstats/blob/36fb7abe2fbbace8ed60b0494ad9271bc7f5247a/src/cursor-export.ts), [fixture](https://github.com/robinebers/cstats/blob/36fb7abe2fbbace8ed60b0494ad9271bc7f5247a/test/fixtures/usage-events-sample.csv).

This parser has no conversation, request or workspace ID. It therefore supports account/model/date totals but supplies no demonstrated identity for assigning a CSV row to a local session. Input/cache field meanings must be reconciled with AI Stack's disjoint token buckets rather than inferred from column labels.

There is a source disagreement: cursor-pulse's newer notes say dashboard export is frontend-generated with no separate CSV endpoint, whereas cstats contains a direct CSV endpoint implementation. The evidence supports coexistence or change as possibilities; it does not settle present availability. Prefer a live owner-approved probe of both routes before choosing CSV automation. [Conflicting export note](https://github.com/cnwinds/cursor-pulse/blob/6017130f010fe5a000550cf87dbefdd3b5f0cb9a/docs/cursor-usage-api.md#L278).

## Concrete reliability gaps

1. **Missing token fields are real enough to require explicit handling.** iair0007's changelog reports accounts stopped receiving `cacheWriteTokens` around 13 August 2026. Its parser distinguishes absent fields from reported zero through `unreportedBuckets`. This is maintainer-observed evidence plus implemented handling, not an independently repeated server test. Copying older parsers that default every absence to zero would falsely imply complete token coverage. [Change record](https://github.com/iair0007/cursor-usage/blob/259ce8a426faf849592ddacb3cb24aae5caed1de/CHANGELOG.md#L87), [presence-aware parsing](https://github.com/iair0007/cursor-usage/blob/259ce8a426faf849592ddacb3cb24aae5caed1de/src/api.ts#L157).

2. **Event identity is weaker than conversation identity.** cursor-pulse hashes timestamp, model and conversation ID. Cursor Economizer uses a unique constraint on timestamp, model and owning user. These are synthesized identities; concurrent requests can collide. iair0007 only deduplicates server `id`/`eventId` values and deliberately keeps records without them, because timestamp/model can collide. Repeated pages without IDs can still inflate a scan. Conversation ID proves a possible join, not per-response deduplication. [Pulse hash](https://github.com/cnwinds/cursor-pulse/blob/6017130f010fe5a000550cf87dbefdd3b5f0cb9a/pulse/integrations/cursor_api.py#L107), [Economizer constraint](https://github.com/cursor-tool/cursor-economizer/blob/d61768edba5398bb318dc12ca06ac3b4bcf6eb3d/src/services/dbService.ts#L14), [pagination policy](https://github.com/iair0007/cursor-usage/blob/259ce8a426faf849592ddacb3cb24aae5caed1de/src/api.ts#L237).

3. **Rows can change after first observation.** Cursor Economizer backfills 90 minutes to pick up delayed token data and updates existing rows. AI Stack's replace-by-day model can help, but only after agreeing the acquisition scope and proving a window is complete. [Backfill constant](https://github.com/cursor-tool/cursor-economizer/blob/d61768edba5398bb318dc12ca06ac3b4bcf6eb3d/src/services/apiService.ts#L49), [incremental overlap](https://github.com/cursor-tool/cursor-economizer/blob/d61768edba5398bb318dc12ca06ac3b4bcf6eb3d/src/services/apiService.ts#L670), [upsert](https://github.com/cursor-tool/cursor-economizer/blob/d61768edba5398bb318dc12ca06ac3b4bcf6eb3d/src/services/apiService.ts#L720).

4. **Account context changes results.** Cursor Economizer explicitly avoids forcing `teamId: 0` after observing empty results for some account contexts; iair0007 still sends it on personal requests. This is a specific interoperability risk rather than a generic reverse-engineering objection. [Request rationale](https://github.com/cursor-tool/cursor-economizer/blob/d61768edba5398bb318dc12ca06ac3b4bcf6eb3d/src/services/apiService.ts#L484), [other implementation](https://github.com/iair0007/cursor-usage/blob/259ce8a426faf849592ddacb3cb24aae5caed1de/src/api.ts#L283).

5. **History limits are not established.** Date filters and historical fetches are implemented, but no inspected source establishes unlimited retention, complete old-model coverage or stable per-request granularity. The chocolatemale script limits pages to 40 and fetches the current billing period. An old extension's README reports a 500-event legacy invoice cap. These are implementation/history constraints, not a universal Cursor retention policy. [Fetch bounds](https://github.com/chocolatemale/cursor-usage/blob/a2f298f161f797036bf96718455e03ccdb42bef4/scripts/fetch_cursor_usage.py#L23), [legacy distinction](https://github.com/xiangz19/cursor_usage_detail/blob/14ad4a569d95b64581723d679d366a86097db844/README.md).

6. **Money has multiple meanings.** Charged cents, token-derived API-equivalent cost, included quota consumption and subscription price are different values. Pulse's `chargedCents or totalCents` fallback even treats a real zero as absent; this should not be copied. Missing cache writes, model aliases, promotional discounts and provider routing all affect repricing. Retain source provenance and coverage, and use AI Stack's existing pricing seam for any estimated amount. [Pulse mapper](https://github.com/cnwinds/cursor-pulse/blob/6017130f010fe5a000550cf87dbefdd3b5f0cb9a/pulse/integrations/cursor_api.py#L98), [separate CSV/computed costs](https://github.com/robinebers/cstats/blob/36fb7abe2fbbace8ed60b0494ad9271bc7f5247a/src/cursor-export.ts#L97).

## What this resolves and what to verify next

The reverse-engineering claim should identify the exact seam. Private database enrichment, private dashboard JSON, private Connect RPC and documented vendor interfaces have different risks. Existing implementations demonstrate that private seams can provide historical measured usage and conversation joins. They do not justify calling every Cursor datum unrecoverable, prospective-only, or inherently an estimate.

The most informative next validation is a consented fixture capture of a known personal IDE conversation: record the API event, its conversation ID, local transcript ID/project, input/output/cache field presence, and duplicate-page behavior. Repeat with concurrent chats, a subagent, a second machine and an older billing period. Test user API-key RPC separately from session-cookie JSON, and retain an explicit unmatched/account-wide bucket. Measure join coverage rather than hiding misses. Compare these results with the official SDK and Admin API findings in the companion research before selecting a production integration path.
