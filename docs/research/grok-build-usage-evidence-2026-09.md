# Grok Build usage identity and replay evidence

Research date: 2026-09-08. Resolves the investigation in [Establish Grok Build usage identity, timestamps, and replay boundaries](https://github.com/alp82/aistack/issues/364). Planning evidence only, with no adapter implementation, private session reads, credentials, paid calls, or publication.

## Conclusion

The documented `grok usage` command is the strongest retrospective token source. It is a JSON projection of `usage.json`, containing mutable per-turn accounting and by-model breakdowns. It is not a per-request billing log. Reading every session and adding every row cannot produce a nonduplicated machine reading: peer forks and resumes copy history, parents fold child spend, and restored remote work can live under the local session root. A complete adapter needs an explicit ownership and coverage contract before implementation. [Command](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-pager/src/usage_cmd.rs), [usage schema and arithmetic](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/usage_file.rs), [copy implementation](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/storage/jsonl/copy.rs), [ledger](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-chat-state/src/usage.rs).

A tempting richer source is unavailable historically: `ResponseCompleted` contains per-response tokens, but its actual producer routes it through the buffered xAI notification path, whose emitter forwards only to the live gateway and does not persist it. Do not infer historical per-call tokens, timestamps, context histograms, or price-period precision from that type. [Producer](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/acp_session_impl/turn.rs#L3177), [send site](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/acp_session_impl/turn.rs#L3337), [buffered sender and emitter](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/acp_session_impl/updates.rs#L322), [wire type](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/extensions/notification.rs#L998).

## Evidence boundary and discovery

All implementation evidence is pinned to public source commit `75810042ca2762aa0b0fa17864f3f68823ccbea5`. The repository says it is periodically synchronized from a monorepo and has a separate released binary distribution. This investigation does not establish the first released version containing this schema or demonstrate that an installed binary matches this revision. Record the actual client version and capability-probe the command during release qualification. A source SHA is an evidence pin, not a minimum supported binary version. [Repository README](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/README.md#installing-the-released-binary).

The first-party guide describes local storage across TUI, headless, and agent stdio. Sessions live under `$GROK_HOME/sessions`, defaulting to `~/.grok/sessions`, grouped by encoded working directory. Long group names use a hash and `.cwd`. `summary.json` indexes sessions; child sessions live in the same normal tree. Directory-scoped interactive listing cannot establish all-machine discovery. [Session guide](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-pager/docs/user-guide/17-sessions.md#storage-layout).

Recommendation: enumerate a bounded, allowlisted session tree with minimal metadata reads, then read usage by known local IDs. The command itself only loads persisted local usage; missing session, missing/empty usage, and malformed JSON are distinct failures. Supplying a turn filter still returns lifetime session totals plus one turn, so consumers must never add both. Bulk file reading can share the same validated decoder after command/file equivalence is tested. [Command](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-pager/src/usage_cmd.rs#L23), [loader](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/usage_file.rs#L321).

## Accounting grain and completeness

| Concern | Source-proven behavior | Adapter consequence |
| --- | --- | --- |
| Identity | A row has `turnNumber` within a restamped `sessionId`; no immutable request ID. Same-process late usage can fold into a row. Inherited number collisions create a new number. | Replace a session snapshot; do not treat `(sessionId, turnNumber)` as an immutable additive event. |
| Timestamp | `endedAt` is set with the persistence writer's UTC clock. A later fold updates it. | Completion/save-day attribution is an approximation. Whole-turn pricing is not exact across a price change. |
| Models | Per-model usage is stored alongside aggregate and primary-model fields. | Price and count per-model leaves once; primary model cannot represent all calls. |
| Cache | Persisted input includes fresh input, cache reads, and cache creation. | Fresh input is inclusive input minus both cache categories. Reject impossible buckets; preserve unknown cache TTL. |
| Output | The ledger total is input plus output; reasoning is a separate informational counter. | Do not add reasoning again. Do not trust provider context-size `total_tokens` as consumption. |
| Calls | Ledger counts main-loop model calls and folded child calls. Side calls such as compaction do not enter it. | Do not label these totals a complete account bill or interpret model-call count as parent-only workflow turns. |
| Costs | Positive reported costs accumulate; partial cost means some counted calls lacked cost. The source test treats zero reported cost as absent. | Missing cost and genuine free usage need independent semantics. Preserve partial flags. |

Sources for table: [mutable row implementation](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/usage_file.rs#L221), [writer](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/persistence.rs#L2426), [normalized sampling tokens](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-sampling-types/src/conversation.rs#L724), [ledger and zero-cost test](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-chat-state/src/usage.rs).

`usageIsIncomplete` is useful positive evidence of omissions but false is not proof of completeness. The response recorder explicitly leaves absent usage unmarked outside task-budget and retry-only contexts. Nested child omissions, drain timeout, and failed application can mark the ledger; some background/prompt completeness signals exist only at report level. Abrupt exits or writer failures can leave the last turn absent: usage persistence is queued and errors log a warning. Failed/retried requests without captured provider usage cannot be reconstructed or priced from this store. [Missing-usage branch](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/acp_session_impl/sampler_turn.rs#L2130), [completeness ownership](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-chat-state/src/usage.rs#L6), [queued snapshot](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/acp_session_impl/turn.rs#L2303), [writer failure](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/persistence.rs#L2329).

## Fork, restore, rewind, and subagent boundaries

- Ordinary copies restamp the usage session ID and preserve turn history. Truncated forks retain usage through the requested boundary and rebuild totals. Resumed-process deltas are based on the new process's live ledger, not subtraction from inherited lifetime totals. [Copy/restamp](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/storage/jsonl/copy.rs#L384), [truncation](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/storage/jsonl/copy.rs#L672), [row implementation](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/usage_file.rs).
- A new subagent fork deliberately does not copy usage, despite copying conversation context. A resumed child does copy usage and records `subagent_resume` provenance. Parent ledgers independently fold child usage by model. Therefore neither counting every child nor dropping every session with a parent reference is correct for all modes. [New child options](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/agent/subagent/mod.rs#L1294), [resumed child options](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/agent/subagent/mod.rs#L1141), [child folding](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-chat-state/src/usage.rs#L140).
- Metadata has parent ID, fork time, kind, context source, parent prompt ID, and inherited conversation-item count. It has no inherited usage-row count or per-call machine ID. `grok_home` is a filesystem path; copies deliberately replace it with the current local path. A remote restore creates a fresh local child referencing the remote session. Directory presence and that path cannot prove where inherited calls executed. [Summary fields](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/persistence.rs#L1029), [fresh copy metadata](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/storage/jsonl/copy.rs#L510), [remote restore relationship](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/persistence.rs#L387).
- The update log is append-only by contract. Full copies preserve rewind markers and abandoned branches; truncated copies apply rewind filtering. Copying changes the notification session ID but preserves other metadata. Ordinary conversation replay should not erase historical billed work in the adapter. Usage truncation found here is in copy handling, not a universal billing undo. [Copy filtering](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/storage/jsonl/copy.rs#L121), [append-only copy](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/storage/jsonl/copy.rs#L226), [session-ID transformation](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/storage/jsonl/mod.rs#L1104).

Persisted notification event IDs can help workflow lineage: their format includes the originating session and a process counter, and replay seeds the counter above retained history. Copied metadata preserves these IDs. However `usage.json` has no join from its turns to those event IDs; the inherited conversation-item count is a different unit. Event identity therefore does not by itself solve inherited token attribution, particularly when ancestors are missing. [Event identity](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell-base/src/util/event_id.rs), [replay seeding](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/agent/mvp_agent/replay.rs#L238), [usage schema](https://github.com/xai-org/grok-build/blob/75810042ca2762aa0b0fa17864f3f68823ccbea5/crates/codegen/xai-grok-shell/src/session/usage_file.rs#L10).

## Candidate policy to decide next

These are recommendations, not established vendor guarantees:

1. Use whole-file usage snapshots for retrospective token evidence, with summary metadata for lineage and discovery. Keep response telemetry or live framing separate from the historical reader.
2. Choose one accounting owner for a parent/subagent family. The parent aggregate is the least invasive baseline, with children supplying activity evidence but no additional token contribution. It can undercount orphaned or not-yet-folded child work; record coverage rather than silently switching to mixed sums.
3. Peer forks and copied resumes require proof of their inherited usage prefix before their marginal turns enter the reading. Exact matching copied rows to available ancestors is a useful validator, not a complete algorithm: ancestors can change, disappear, or originate remotely. Do not use token similarity, file mtime, or fork time alone as conclusive identity.
4. When ownership or inherited boundaries cannot be proved, quarantine that contribution with an explicit reason. A stricter initial subset can include known local, uncopied parent families, but absence of lineage metadata alone is not proof for legacy or externally copied files. The complete destination should cover supported modes through an explicit evidence policy, rather than silently accepting guessed totals.
5. If maximal coverage requires an upstream improvement, request a persisted per-response receipt containing stable origin-session/call identity, model/provider, response timestamp, and copy lineage. A prospective owner-approved collector is another distinct design option; it cannot recover unavailable history.

## Minimal qualification matrix

Use synthetic offline fixtures derived from source first, then owner-sanitized output from a known released binary. Source tests are evidence, not executed validation in this investigation.

| Fixture family | Required assertion |
| --- | --- |
| Fresh TUI, headless, agent stdio; custom GROK_HOME and long cwd | All supported roots discover once; command/file output equivalent; absent usage is unavailable. |
| Multi-call and multi-model turn, cache read/create, reasoning | Sum model leaves once; normalize disjoint buckets; reject invalid sums; retain incomplete/partial evidence. |
| Same-process late interjection, resumed process, colliding turn numbers | Re-reading replaces totals; row mutation and timestamp change never become additive duplicates. |
| Peer fork, nested fork, truncated fork, parent later extended | Copied history counts once; boundary failures produce explicit quarantine. |
| Fresh child, resumed child, nested child, background completion, missing parent | Parent fold ownership holds; orphan/late usage does not cause guessed reconciliation. |
| Rewind then new work, compaction, interrupted response, retry, hard exit | Billed abandoned work stays counted when retained; omitted side calls and missing final usage stay uncovered. |
| Remote restored session, missing ancestor, copied root, duplicate session IDs | Local path is not accepted as machine origin; uncertainty is surfaced. |
| Midnight and price-change turn; Stop-triggered scan before writer flush | Timing approximation is explicit; later reread replaces the snapshot without losing or doubling a day. |
| Missing/malformed/empty sidecar, older client, unknown added fields | Corruption and unsupported capability fail narrowly; no fabricated zeros or inferred historical tokens. |
