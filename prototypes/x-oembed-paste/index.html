X owner-paste flow with oEmbed rendering

The question: does the owner-paste lane from the news pipeline spec work end to end? Paste a real X post link. The page fetches the free oEmbed endpoint live, stores the post ID with the official embed, and renders it. The page also shows the failure cases: a deleted post and a broken link. Round two adds profile paste: a profile link stores as its own kind, the page renders what X still gives for it, and a captured timeline lets you pick recent posts from the profile.

What the backend sees

This page fetches with JSONP, because the endpoint sends no CORS headers. JSONP hides the HTTP status code, so the browser only knows that a fetch failed. The real collector is a Convex action. It sees the full response. These are real responses, captured with curl on 2026-08-19.

Facts this prototype settled

  • publish.twitter.com answers 301 to publish.x.com. The collector calls the new host directly.
  • A live post answers 200 JSON. The html field is a blockquote with the full post text, plus one widgets.js script tag. omit_script=1 removes the script tag, so the page loads it once.
  • A deleted or nonexistent post answers 404 with an HTML error page, not JSON. The collector must branch on the status code before it parses.
  • A broken URL answers 400 JSON: {"message":"bad url, ..."}.
  • A profile link is accepted too, as its own kind. The endpoint answers 200 with a timeline anchor. A profile link must never pass as a post, or the lane stores the wrong thing.
  • A profile embed cannot show a feed anymore. X cut embedded timelines in 2023, and the data endpoint behind them answers an empty body today. The profile card renders the live answer, so judge it there.
  • Profile paste CAN still simplify the flow another way: an unofficial endpoint returns the last ~100 posts of a profile with IDs and text. Free, rate limited, undocumented. The demo server runs that pull live for any pasted profile. Pick posts from the list, and each pick runs the normal post lane. Whether the pipeline may build on that endpoint is the X research lane question, and docs/research/x-profile-posts-2026-08.md weighs the options.
  • The endpoint accepts x.com, twitter.com, and links with tracking params. The parser normalizes all of them to one canonical URL, so one post never stores twice.
  • No CORS, but JSONP works with callback=. A browser page can fetch live. The spec still routes collection through a Convex action, which is the better place: it sees status codes.
  • If a post dies after we stored it, the stored blockquote keeps the text and the link. Only the hydration to a styled card fails. The stored item stays readable.
